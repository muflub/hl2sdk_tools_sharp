# Rooms features sample

A room library on the 3x3 kit whose rooms carry the map features the
`samples/rooms-3x3` kinds do not, and one level of them with its three
whole-level turns. Every feature goes through the same commands as the 3x3
sample: `ssmap room`, `ssmap link`, `ssmap link --flatten`, `ssmap vbsp`,
`ssmap check`, and the test suite holds each linked level to its flattened
compile.

Everything in this folder except this README is generated by
`SourceSharp.MapGen.Rooms.RoomsFeaturesSample` and checked by a test to be
exactly what the generator writes. Do not edit the files by hand; change
the generator and regenerate with `tools/RoomsSample --features
samples/rooms-features`.

**Why a sibling and not the 3x3 sample grown.** The rooms design (section
16) planned to add these features to the 3x3 kinds. The 3x3 sample is
pinned from too many sides for that: its generator's own monolithic map
draws boxes only, its equivalence facts sample every point of its levels
and trace between every pair of rooms, its seeded levels are pinned as
`ssmap layout` writes them, and every rooms PR since water recorded that
its levels link to the same bytes as before. A pool, a displacement or a
tall room in a 3x3 kind would move all of those at once. Here the same kit
carries each feature, and the 3x3 levels stay the regression they are.

## What is here

| Path | What |
| --- | --- |
| `gameinfo.txt` | A game that mounts only this folder, so the sample compiles with no Steam install. |
| `detail.vbsp` | The detail type the grass grows: upright sprites, so no prop model is needed. |
| `materials/rooms3x3/*.vmt` | The kit's materials. |
| `materials/roomsfeatures/*.vmt` | The grass (`%detailtype`), the pools' water (cheap, fogged, unlit) and its underside. |
| `rooms.vmf` | The library: four rooms in a line along +x, each marked by an `info_room`. |
| `levels/features.yaml` | The level. |
| `levels/features_turn{1,2,3}.yaml` | The level turned a quarter, a half and three quarters. |

### The rooms

| Room | Doors | What it carries |
| --- | --- | --- |
| `garden` | all four | a slab whose top grows grass detail props; an `info_poi` with `map_marker fountain` and `map_label Fountain`; the room's own `map_label Garden`; an `info_player_start` |
| `tower` | east, west | `room_height 512`: a tall room, its doors where a cube's are with a lintel above them, a pillar to its ceiling, a second light near the top, `map_label Tower` |
| `ridge` | east, north | a power 3 displacement with a 40-unit ridge down its middle, whose flanks are too steep to stand on, and a power 2 patch sharing its east edge |
| `pool` | east, west, north | water from the west plug to the east one, 48 units deep, declared on both walls as water sockets (`water_east "64 roomsfeatures/water"`, and west) |

### The level

```yaml
library: ../rooms.vmf
rows: 2
columns: 3
grid:
  - [garden, tower, ridge@180]
  - [pool,   pool,  ridge]
```

The two pools' water joins through their shared doorway, one body of water
at one level. Each pool's other water socket is capped (the grid's edge on
the west, the ridge's plain wall on the east), which is allowed: a water
socket may be capped, or jointed to another at the same level, never
jointed to a dry socket. `ssmap layout` does not read water sockets, so
this level is written by hand rather than drawn from a seed.

## Build and link it

```sh
ssmap rooms rooms.vmf                  # lists heights, detail props, displacements, water and each room's map
ssmap room rooms.vmf -game .           # lit, cooked and with navigation, as by default
ssmap link levels/features.yaml -out out/features.bsp
ssmap check out/features.bsp

# the reference: the same level as one VMF, compiled whole
ssmap link levels/features.yaml --flatten -out maps/features.vmf
ssmap vbsp maps/features.vmf
ssmap map2d maps/features.bsp -level levels/features.yaml -out maps/features.map2d
```

The link writes `out/features.bsp`, its level map `out/features.map2d`
(the garden's marker and the two labels on it, the ridge's crest a gap
between the ground either side) and its navigation `out/features.nav3d`
(version 3: the tower's cell is 512 units tall). `ssmap check` reports one
warning on every level, as on the other samples: the level has no cubemap
sample.

## What the tests check

`RoomsFeaturesSampleCommandsTests` runs the commands above on an in-memory
copy of this folder, for the level and each of its turns: the link warns of
nothing, the linked map and the flattened compile pass `ssmap check` with
that one warning, the linked `.map2d` is the flattened compile's map cut by
the level file byte for byte, the `.nav3d` is the flattened compile's
navigation grid run for run, every point of a lattice over the level holds
the same contents in both maps (the doorway's water included), the two
pools are one water record, and the linked map carries the garden's detail
props and the ridges' displacements. `RoomsFeaturesSampleTests` holds this
folder to its generator and the library to the pipeline's reader.

The flattened compile scatters its own detail props (another random draw of
the same density over the same surface), so the two maps agree on detail
props in distribution, not prop for prop; the doorways' side faces are
missing in the link, as in every linked level.
