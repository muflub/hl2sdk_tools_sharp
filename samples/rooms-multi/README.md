# Rooms multi-library sample

Two room libraries on the 3x3 kit and levels that place rooms of both: the
multi-library sibling of `samples/rooms-3x3` (the rooms design, 17.12). It
shows a level naming its libraries by key, rooms of one name in both
libraries, an alias, tall rooms of two heights, one sun shared under the
singleton rules, one 3D skybox, a combined pack built with
`ssmap roompack`, and levels drawn by `ssmap layout -large`.

Everything in this folder except this README is generated by
`SourceSharp.MapGen.Rooms.RoomsMultiSample` and checked by a test to be
exactly what the generator writes. Do not edit the files by hand; change
the generator and regenerate with `tools/RoomsSample --multi
samples/rooms-multi`.

## What is here

| Path | What |
| --- | --- |
| `gameinfo.txt` | A game that mounts only this folder, so the sample compiles with no Steam install. |
| `materials/rooms3x3/*.vmt`, `materials/roomsmulti/sky.vmt` | The kit's materials and a `%compileSky` sky. |
| `base.vmf` | Library `base`: the 3x3 kit's five rooms (`cross`, `tee`, `corner`, `hall`, `end`) and a `light_environment` in its gaps. |
| `caves.vmf` | Library `caves`: its own `hall` and `end`, `cavern` and `gallery` (512 tall), `shaft` (768 tall, a sky ceiling), the skybox room `sky`, and the same `light_environment`. |
| `levels/mixed.yaml` | A 3 x 3 level of both libraries. |
| `levels/mixed_turn{1,2,3}.yaml` | The same level turned whole, so each tall room stands at every rotation. |
| `levels/large_{1,2}.yaml` | Levels `ssmap layout` draws from both libraries with `-large` (below). |

### The singletons

`base` is listed first, so its sun is the level's; `caves` has the same
`light_environment` to the key, which the link, the flatten and
`ssmap rooms` report once as `library caves: 1 singleton(s) equal to
library base's dropped (light_environment).` Only `caves` has a 3D skybox,
so the level takes it (a singleton only a later library has is used, taken
from the earliest library that has it). `shaft`, whose ceiling is sky, is
the one room the sun reaches: it is baked under that sun and over that
skybox whether the libraries are packed apart or together.

### The mixed level

```yaml
libraries:
  base: ../base.vmf
  caves: ../caves.vmf
rows: 3
columns: 3
aliases:
  H: caves.hall
grid:
  - [base.end@270, gallery@90, shaft@180]
  - [tee@270,      cross,      cavern@90]
  - [corner,       H,          caves.end@180]
```

`hall` and `end` are in both libraries, so a cell names them qualified
(`base.end`, `caves.end`) or by an alias (`H`); every other name is in one
library and is written bare.

### The `-large` levels

```sh
ssmap layout base=base.vmf caves=caves.vmf -rows 4 -columns 4 -seed 1 \
    -large 0.4 -group 3 -out levels/large_1.yaml
```

writes `large_1.yaml`, and `-seed 2` `large_2.yaml`: 40% of the cells are
taken by groups of up to three tall rooms, each group of one height where
it can be, joined through its own doors and reached through the standard
rooms around it.

## Build and link it

```sh
# one pack per library, beside it: base.roompack, caves.roompack
ssmap room base.vmf -game .
ssmap room caves.vmf -game .
ssmap link levels/mixed.yaml -out out/mixed.bsp

# or both libraries in one pack, each under its namespace
ssmap roompack -out multi.roompack base=base.vmf caves=caves.vmf -game .
ssmap link levels/mixed.yaml -rooms multi.roompack -out comb/mixed.bsp

ssmap rooms levels/mixed.yaml
ssmap check out/mixed.bsp comb/mixed.bsp
ssmap link levels/mixed.yaml --flatten -out maps/mixed.vmf
ssmap vbsp maps/mixed.vmf
```

The two libraries share one worldspawn and one sun, so a level linked from
the combined pack is the level linked from the separate packs but for the
pack and level ids its worldspawn and `.nav3d` record; the combined pack
has settled the sun at pack time, so its link prints no singleton line.

## What the tests check

`RoomsMultiSampleCommandsTests` runs the commands above on an in-memory
copy of this folder: every level links from the separate packs and from
the combined pack to maps that differ only in those ids, with the same
`.map2d`; each map and the flattened compile pass `ssmap check` with the
one warning every sample level has (no cubemap sample); the linked
`.map2d` is the flattened compile's map cut by the level file, byte for
byte; each `.nav3d` (version 3, for the tall rooms) is the flattened
compile's navigation grid run for run; and the `-large` levels are what
`ssmap layout` writes for their seeds, each placing tall rooms.
`RoomsMultiSampleTests` holds this folder to its generator, and the
libraries, their singletons and the mixed level's names to the pipeline's
readers.
